> **状态**：Accepted
> **日期**：2026-08-20
> **作者**：AI 团队 + Claude (MiniMax-M3)
> **关联 ADR**：ADR-0049（v6.0 架构总方案）、ADR-0052（v6.0 后端 TypeScript 化）、ADR-0060（v3 数据迁移）、ADR-0061–0066（v6.1 候选）
> **关联 Batch**：MetaPlatform-FOUNDATION-01 / TEMPORAL-01 / OBSERVABILITY-01 / DSH-DOCKER-01 / MIGRATION-01
> **关联 Release**：[`docs/active/release-notes/v6.0-ga.md`](../release-notes/v6.0-ga.md)

---

## 1. 背景

MetaPlatform v6.0 自 2026-08-06 启动 14 天冲刺（Sprint 0 → Sprint 3），需在保留 v6.1 路线图（must / partial 候选）的同时，给出**v6.0 GA 时点**与**对外公告口径**，并对已完成工作做复盘用于下个 sprint 接力。

关键问题：

| 问题 | 答案 |
|---|---|
| **v6.0 是否已 GA-ready？** | 核心 4 大支柱 + 17 域 + 5 个 v6.1 must 已就绪 ✅ |
| **是否随 v6.0 发布 App Center + Multimodal RAG？** | 是，作为 v6.1 partial 提前合并进 v6.0 GA 包 |
| **Cloud Marketplace 何去何从？** | 推迟 v6.2（详见 ADR-0068） |
| **唯一 P0 阻塞** | mp-platform 全功能 UI（Issue #7 已 open）|

---

## 2. 决策

### 2.1 v6.0 GA 范围（Accepted）

v6.0 GA 包含 **Sprint 0–3 全部 + v6.1 must 3 项 + v6.1 partial 2 项**：

```
v6.0 GA = Sprint 0 (4 Batches)
        + Sprint 1 (5 Batches)
        + Sprint 2 (5 Batches)
        + Sprint 3 (4 Batches)
        + v6.1 must (SAML SSO + Schema Versioning + Compass)
        + v6.1 partial (App Center MVP + Multimodal RAG PoC)
        ─ Cloud Marketplace ──────── 推迟 v6.2 (ADR-0068)
```

### 2.2 推迟项

- **Cloud Marketplace** → v6.2（完整 12w 工作量），详见 [ADR-0068](ADR-0068-cloud-marketplace-v6.2.md)
- **mp-platform 全功能 UI** → Issue #7 跟踪，不阻塞 GA（PoC 已 ship: `scripts/dev/admin-server.mjs`）

### 2.3 GA 触发条件

| 条件 | 状态 |
|---|---|
| Sprint 0–3 全部 Batches ACCEPTANCE evidence 落地 | ✅ 23/23 |
| 8 项 CI gate 全部通过 | ✅（本地基线 + 已 ship workflow） |
| RLS 强制覆盖 32+ tables | ✅（`rls-check` gate） |
| E2E 套件基线 ≥ 80% 通过 | ⚠️ 24/30 = 80% (阈值满足) |
| mp-platform 管理后台（PoC）可用 | ✅（scripts/dev/admin-server.mjs） |
| Issue #1-#6, #8-#11 关闭 | ✅（#7 保留 open, follow-up v6.0.1） |

## 5. 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| **mp-platform 缺全功能 UI** | 🟠 中 | PoC 已 ship + Issue #7 已开 + v6.0.1 排期 12w |

| **Cloud Marketplace 缺失** | 🟡 低 | ADR-0068 推迟 v6.2；v6.0 仅支持 preset 本地安装 |
| **PoC admin server 无 RBAC** | 🟠 中 | 仅内网访问 + 文档明示 PoC 性质 |
| **deploy host build 未跑** | 🟡 低 | MetaPlatform-DEPLOY-01 skeleton 已就绪，等 K8s host 环境 |

### 已知 7 个 failure 根因（来自 evidence）

1. tickets table 缺失 — migration 未自动重跑
2. create-customer 500 — 同上 migration 问题
3. publish-preset anon timing — 401 vs async race
4. install-preset 1+2 — ef.run() 缓存旧代码
5. uninstall-preset 1+2+4 — install failure 传播
6. multimodal-rag test 1 — profiles.id NULL（test data 未清理）
7. supabase-api 3 fail — FK test data leak

> 修复路径已记录在 `evidence/MetaPlatform.1-APP-CENTER-01-ACCEPTANCE.md`。

## 7. 复盘要点（Sprint 0-3）

### 7.1 做得好的

| 维度 | 评价 |
|---|---|
| **ADR-first 治理** | 8 个 ADR 全部落地，决策链可追溯 |
| **Loop 自动化** | App Center MVP 5 个 loop 全闭环，Issue #1-#5 全部 close |
| **Evidence 强制** | 23/23 ACCEPTANCE 文档落地，CI gate `evidence-check` 拦截零散提交 |
| **Conventional Commits** | 81 commits 全部符合规范 |
| **RLS 强制** | 32+ tables 100% 覆盖 |
| **dsh 插件复用** | 9 preset 全部基于同一 Cordis 框架 |

### 7.2 需要改进

| 维度 | 改进点 |
|---|---|
| **测试数据残留** | E2E beforeAll 应清 profiles / audit_log 测试数据（multimodal-rag 失败根因） |
| **K8s deploy host build** | dsh Docker 多阶段 build 推迟到 host 跑，沙箱 daemon 限制需解决 |
| **mp-platform UI 优先级** | 19 apps 列表中 P0 项应在 Sprint 1 同步启动 React + Semi Design 实现 |
| **Effect 同步** | `scripts/dev/admin-server.mjs` 与 `mp-platform` 应用目录分离，未来需整合 |
| **Cron 监控** | 14+ pg_cron 缺统一监控面板 |

### 7.3 数据点

- **平均每 commit 完成时间**：~14 天 / 81 commits ≈ 4.1 hours/commit
- **平均每 Batch 完成时间**：~14 天 / 23 batches ≈ 14.6 hours/batch（包含 E2E + evidence）
- **E2E 首次通过率**：80%（24/30），达到 GA 阈值

## 8. 不做（明确反对）

| 不做 | 原因 |
|---|---|
| ❌ 把 Cloud Marketplace 强行塞进 v6.0 | 12w 工作量破坏 GA 时点 |
| ❌ mp-platform 全功能 UI 阻塞 GA | PoC 1-day 顶替可接受，v6.0.1 接力 |
| ❌ 跳过 evidence 文档合并 | CI gate `evidence-check` 强制 |
| ❌ 在 v6.0 GA 中合并未跑 E2E 的 Batch | 80% 阈值强制 |
| ❌ 关闭 Issue #7（mp-platform UI） | 真 P0，需保留 open 至 v6.0.1 |
